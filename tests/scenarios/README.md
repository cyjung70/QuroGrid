1. **확정 시나리오**: Spec 5.1절에 ID가 있는 GS-001~GS-010

### 시나리오별 확인 사항

- **GS-003** — **O-05 결정(2026-10-28): 기본 방향 오른쪽**, 아래쪽은 옵션. **결정(2026-10-28): "마지막 셀 Enter 시 새 행 추가"를 그리드 옵션으로 둡니다** (Spec 4.7에 없던 옵션 — 보완). 기본값은 잠정으로 **끔**(다음 행 첫 셀로 이동, 마지막 행이면 머무름)입니다. 테스트는 방향 옵션 2가지 × 새 행 옵션 조합을 매개변수로 돌리고, 기본값(오른쪽)을 별도로 검증합니다.
- **GS-004** — "부족 행 자동 추가"는 Spec 4.7에서 **옵션**입니다. 옵션 ON/OFF를 모두 검증합니다. "서버 호출 1회"는 JS Interop 호출 횟수로 측정합니다.
- **GS-005** — "안내"의 형태(토스트/툴팁/메시지 바)가 Spec에 없습니다. 메시지는 리소스 키로 내보내는 것만 검증하고 표시 방식은 화면 쪽에 맡기는 안을 제안합니다.
- **GS-006** — **결정(2026-10-28): 0건 일치면 팝업을 띄우지 않습니다.** Spec 4.6("미일치·복수 일치 시 팝업")과 다릅니다. 0건일 때 입력값 처리는 잠정으로 **확정하지 않고 편집 상태 유지**로 두고(안내는 앱이 `CellMark`로), 테스트는 3개(1건/0건/복수)로 나눕니다.
- **GS-007** — **결정(2026-10-28): 날짜 포함.** 해석은 DataSet `TrySetText(row, field, text, culture)`로 단위 테스트하고, 붙여넣기 흐름은 E2E로 검증합니다. 해석 실패 시 값은 바뀌지 않고 `false`를 돌려줍니다 (안내 방식은 GS-005와 함께 정함).
- **GS-008** — **결정(2026-10-28): 셀 오류 판정은 그리드가 아니라 앱이 한다. 그리드는 Minus 표시만 한다.** 앱이 `SetCellMark(row, field, CellMark(Error|Warning, 리소스 키))`로 지정하고 그리드는 색·툴팁으로 그립니다. 저장 차단도 앱이 합니다. DataSet 부분은 단위 테스트로 끝났고, 그리드 표시는 Phase 2 bUnit에서 검증합니다. **Spec 4.9("그리드 검증 훅", OFF 시 그리드가 저장 차단)와 다릅니다.**
- **GS-009** — **결정(2026-10-28): 저장 API는 QuroGrid와 분리된 서버이며, DataSet이 저장 API와 통신한다.** `SaveAsync(http, url)`이 변경분을 POST하고, 2xx면 `AcceptChanges` 후 앱이 재조회합니다(응답 본문은 쓰지 않음). 409는 `Conflict`, 그 밖은 `Failed`로 돌려주며 변경분은 유지합니다. 버전 충돌 판정 자체는 저장 API 쪽 테스트 범위입니다.
- **GS-010** — "미저장 변경 유지"는 **같은 회로로 재연결**된 경우만 해당합니다. 회로가 소멸된 경우는 O-03(잠정: 보관 안 함, 경고만) 범위이므로 별도 시나리오로 둡니다(후보 C-38).

**Phase 2 3-5 구현 메모 (Addendum A-20·A-21)**
- `QuroDataSet.HasChanges`: Normal이 아닌 행이 있으면 true. 그리드 루트에 `data-dirty`로 그려 JS가 끊김 경고에 씁니다.
- 이탈 경고는 Blazor `NavigationLock`(창 닫기·새로고침·`NavigateTo`)과 JS 링크 클릭 확인(향상된 탐색)을 함께 씁니다.
- 끊김 안내는 서버가 그릴 수 없으므로 미리 그려 두고 JS가 `data-offline`·`data-lost`로 보이게 합니다. 끊김 중 서버 호출 없음.
- 재연결 후 같은 회로인지는 그리드 인스턴스 ID를 서버에 물어 확인합니다 (회로마다 다른 값). 다르면 유실 표시를 남겨 다시 그려진 화면이 안내합니다.
- 샘플: 끊긴 회로 보관 시간 설정 `Circuit:RetentionSeconds`(기본은 .NET 기본값). E2E 샘플 서버는 5초로 회로 소멸을 재현합니다.
- E2E는 SignalR WebSocket을 가로채 끊고, 재연결 요청(negotiate)을 붙잡아 끊김 상태를 유지합니다.

**Phase 2 3-3 구현 메모 (Addendum A-10·A-12~A-15)**
- Insert: 활성 행 바로 아래에 행 추가(A-15) 후 새 행의 첫 편집 가능 셀로. Ctrl+Delete: 선택 범위의 행을 서버 호출 1회로 삭제, 활성 셀은 같은 순번(없으면 마지막) 행의 같은 열로.
- 툴바용 그리드 메서드 `CopySelectedRows()`·`DeleteSelectedRows()`: 선택 범위는 JS 소유라 JS에서 행 키를 받아 처리합니다.
- 행 복사: 표시 순서대로 각 원래 행 바로 아래에 `Inserted`로. 복사 행도 `OnRowAdding(SourceRowKey)`를 거칩니다 (샘플은 여기서 행 번호를 새로 줌).
- `OnSelectionChanged`: 앱이 구독했을 때만 JS가 보냅니다(`init` 옵션). 활성 행이 멈춘 뒤 100ms (A-13).
- `QuroColumn`의 `Required`·`Min`·`Max`는 컬럼 등록·변경 시 `DataSet.SetRule`로 넘깁니다.
- `OnRowDeleted`(A-14): 삭제 호출 1회에 한 번, 실제 삭제된 행 키. JS에서 시작한 삭제 뒤 앱 화면(변경 수 등)을 갱신하는 시점입니다.

**Phase 2 3-2 구현 메모 (Addendum A-03·A-04·A-06)**
- 부족 행 자동 추가 `AddRowsOnPaste` 기본 켬. 추가 행도 `OnRowAdding`/`OnRowAdded`를 거칩니다. 열이 넘치면 버립니다.
- 읽기 전용(삭제 표시 행 포함)·해석 실패·`OnCellValueChanging` 취소 셀은 건너뛰고 `OnPasted`로 `PasteSkip(행 키, 필드, 사유 키)`를 넘깁니다. 안내 표시는 앱이 합니다.
- 붙여넣기 시작 위치는 선택 범위의 왼쪽 위 셀. 편집 중 붙여넣기는 에디터가 받습니다.
- 복사는 화면 표시 값(서식 포함)을 탭·줄바꿈(`\r\n`)으로. 탭·줄바꿈·큰따옴표가 있는 값은 큰따옴표로 감쌉니다.
- 선택 범위는 JS 소유 (그리드 루트 `data-selection`). 단일 값으로 범위 채우기(엑셀의 채우기 붙여넣기)는 Spec에 없어 구현하지 않았습니다.
- 성능 메모: 붙여넣기는 Interop 1회지만, 셀마다 값 변경 이벤트를 받는 화면은 이벤트마다 다시 그려집니다 → 4-3에서 측정 (A-26).

**Phase 2 3-1 구현 메모 (해석·잠정)**
- Enter(오른쪽)는 Tab과 같은 순서로 **편집 가능한 셀만** 이동합니다 (읽기 전용 열 건너뜀). 화살표는 읽기 전용 셀도 지나갑니다.
- Enter(아래)는 같은 열의 다음 행으로 이동합니다. 마지막 행·마지막 편집 가능 셀에서 새 행 옵션이 꺼져 있으면 제자리입니다.
- Tab은 마지막 셀에서 새 행을 추가하지 않습니다 (Spec 4.7은 Enter에만 옵션 언급).
- 활성 셀 표시는 JS가 소유합니다 (R1): 그리드 루트의 `data-active-row`·`data-active-field`와 별도 style 규칙. 서버 렌더가 셀 class를 바꿔도 지워지지 않습니다.
- 서버 응답을 기다리는 동안 들어온 키는 순서대로 처리합니다 (빠른 입력 `B77` + Enter도 유실 없음).
- 에디터는 서버가 그리지만(편집 시작 1회 호출) 편집 중 키 입력은 서버로 보내지 않습니다. E2E에서 SignalR 전송 프레임 0건으로 검증합니다.

**Phase 2 2차 구현 메모 (Spec 4.10에 인자 정의가 없어 잠정으로 정한 것)**
- 취소 가능한 이벤트(`OnCellValueChanging`·`OnRowDeleting`·`OnPasting`)는 인자의 `Cancel = true`로 막습니다. `OnRowAdding`은 취소 없이 기본값 세팅만.
- `OnCellValueChanging` 취소·해석 실패 시 값은 그대로이고 **편집 상태를 유지**합니다. 값이 바뀌지 않은 커밋은 이벤트 없이 편집만 닫습니다.
- `OnRowDeleting`은 **행마다** 발생하고, 취소한 행만 남습니다 (일괄 삭제도 서버 호출은 1회, R3).
- 붙여넣기는 셀마다 `OnCellValueChanging`/`OnCellValueChanged`를 발생시킵니다 (금액 재계산이 붙여넣기에도 적용되도록). 서버 C# 안의 호출이므로 JS Interop은 1회(R3).
- 이벤트를 부모 화면이 받아 다시 그려져도 **바뀐 행만 렌더**됩니다 (행 표시에 영향을 주는 파라미터가 바뀐 경우만 전체 렌더).
